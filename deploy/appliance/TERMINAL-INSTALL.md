# Existing-account terminal target installation

`tools/install_terminal_target.py` prepares and applies one append-only SSH
application-key installation for an existing non-root Unix account. Source
tests use synthetic ownership/files only. Actual installed SSH/tmux acceptance
remains an operator gate; this tool never authenticates, creates an account,
starts tmux, changes global sshd policy, or reloads/restarts a service.

The dedicated tmux socket separates this application's server/session from the
account's default socket. It does not isolate the Unix account. The account can
run commands and access its ordinary files; review its shell startup, existing
authorized keys, effective sshd policy and trust before installation. The
launcher starts `/bin/bash --noprofile --norc` through the existing reviewed
`terminal_launcher.render()` output, with an empty environment and explicit
tmux socket/config. The SSH account shell executes the forced launcher before
that environment clearing; account startup behavior needs separate review.

Generate the application key on the portal host, retain its private file there,
and transfer only its public `.pub` file to a root-protected path on the SSH
target. No private key is read or generated by this installer. Source addresses
must be the exact trusted addresses actually observed by the target's SSH
server through the approved transport. DNS, CIDR, wildcard, loopback, duplicate
and unsorted source values are refused.

External root-private configuration (synthetic addresses/account only):

```json
{
  "schema": 1,
  "username": "terminal",
  "from_addresses": ["192.0.2.5"],
  "public_key_path": "/protected/application.pub",
  "session": "portal"
}
```

The existing account must have a reviewed bash shell and safe user-owned home
and `.ssh` directories. Its existing `authorized_keys` must be a bounded regular
single-link file, mode0600 or0644, owned by the account or root. Group/other
writable ancestry, symlinks and hardlinks are refused. Existing file bytes,
owner, group and mode are preserved. The application public identity must not
already occur in that file, even in a comment. A missing authorized_keys is
refused and requires a separate operator decision rather than implicit setup.

Fixed installed product paths:

| Path | Owner/mode |
| --- | --- |
| `/usr/local/libexec/portal-tmux` | root:root0755 |
| `/etc/guacamole-portal-terminal` | root:root0755 |
| `/etc/guacamole-portal-terminal/tmux.conf` | root:root0644 |
| `/var/lib/guacamole-portal-terminal` | root:root0755 |
| `/var/lib/guacamole-portal-terminal/tmux` | existing account UID/GID0700 |
| `/var/lib/guacamole-portal-terminal/tmux/socket` | created later by that account's tmux |

The root-protected product parent allows traversal while the account-owned
mode0700 tmux directory protects its socket. The launcher, config and product
roots must be absent before preparation. `/usr/local/libexec` may already be a
protected root directory or be created if absent; existing contents are retained.
No existing default tmux server/socket is contacted or removed.

```sh
sudo python3 tools/install_terminal_target.py prepare \
  --directory /protected/new-terminal-case --config /protected/terminal.json
```

Preparation makes a new private fsynced case, backs up full authorized_keys
bytes before any target change, and stores the public key/config plus exact
rendered products. `plan.json` binds the complete original account/shell/UID/GID/
home and directory identities, authorized_keys bytes/inode/metadata, public key
bytes/metadata, absent product paths, root parent state and current source/native
executable hashes. Source and native prerequisites must live under protected
root-owned ancestry. Inspect the plan, full diff and appended key line before
independently approving its exact SHA256.

```sh
sudo python3 tools/install_terminal_target.py apply \
  --directory /protected/new-terminal-case --plan-sha256 EXACT_REVIEWED_SHA256
```

Apply locks the case, revalidates the complete original state and records a
single-use durable intent. It creates only the owned product directories,
launcher and tmux config, verifies their exact bytes/ownership/modes and an
unused socket directory, and appends authorization LAST. It pins the home/.ssh
directories with no-follow descriptors, preserves the complete old file prefix,
adds a line terminator only if necessary, writes a new temporary file with the
original owner/group/mode, rechecks the original full bytes/inode/metadata,
then atomically replaces authorized_keys and fsyncs its directory. Temporary
file identity/content and final authorization are checked. Concurrent changes
are refused where observed; the existing trusted account retains control over
its own `.ssh` directory, so installation must be coordinated with that owner.

The sole added line has exact literal `from="..."`, `restrict,pty` and
`command="/usr/local/libexec/portal-tmux"` options plus the canonical Ed25519
public key. `restrict` disables port, agent and X11 forwarding and user rc;
`pty` deliberately re-enables only PTY allocation. Missing or unexpected
SSH_ORIGINAL_COMMAND is rejected by the unchanged renderer before tmux runs.
The new key's comment is fixed. Existing keys/options/comments remain intact.

A partial failure leaves its case and owned artifacts for review. Before the
last append, authorization remains unchanged. Failure after the atomic append
may mean access was installed even if its result receipt failed; reconcile
actual bytes rather than retrying. Every attempted case is nonreplayable,
including interrupted/uncertain attempts. Errors preserve the original failure
even when the failure receipt cannot be persisted. Output contains only fixed
success/action/error class, never native diagnostics or key material.

Rollback is deliberately manual and separately approved. First prove the new
application key is unused, owner sessions are clear, and the dedicated tmux
server/socket is unused. Require the entire current authorized_keys SHA and
owner/group/mode to equal the staged `authorized_keys-new` artifact; if another
key or metadata changed, stop for review. Only then atomically restore exact
backup bytes with the original owner/group/mode and fsync. This removes only
the one known appended line because the complete current file matched first.
Never delete/rename existing keys, restore an older unrelated key file over
new changes, kill the account's tmux servers, or remove a live socket. Remove
owned product files/directories only after proving exact installed hashes and
ownership and no contents/sessions to preserve. Keep private case evidence.

```sh
sudo env PYTHONPATH=deploy/appliance:deploy/appliance/tools \
  python3 -m unittest deploy/appliance/tools/test_install_terminal_target.py
python3 -m unittest discover -s deploy/appliance/tools -p test_terminal_launcher.py
```

These tests perform no SSH, account creation, native tmux or service operations.
Root filesystem tests use synthetic files/UIDs under /run, never an actual
account's authorization or production product paths.
